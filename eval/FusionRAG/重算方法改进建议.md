## 一、短期改进（可立即实施）

### 1.1 引入答案质量验证机制

**问题**：Rate=0.3对不完整答案有100%置信度，无法自我检测。

**建议A：双路径验证**
```python
def generate_with_verification(
    model, tokenizer, passages,
    primary_ratio=0.3,
    verification_ratio=1.0,
    threshold=0.5
):
    # 主路径：使用低ratio快速生成
    answer_primary, logits_primary = generate(ratio=primary_ratio)

    # 验证路径：使用高ratio生成（可以更短的max_tokens）
    answer_verify, logits_verify = generate(
        ratio=verification_ratio,
        max_tokens=len(answer_primary) + 10  # 只多生成一点
    )

    # 检查答案长度差异
    length_ratio = len(answer_verify) / max(len(answer_primary), 1)

    if length_ratio > (1 + threshold):
        # 答案长度差异>50%，可能信息缺失
        return answer_verify, "verification_failed"
    else:
        # 答案长度相近，使用快速版本
        return answer_primary, "verified"
```

**收益**：
- 只需要额外10-20%的计算成本（验证路径生成更少tokens）
- 可以捕获大部分信息缺失问题
- 保留了大部分加速收益

### 1.2 基于Attention差异的动态调整

**问题**：Answer部分的attention L2达到3.31，远高于Query部分的1.63，预示着信息缺失。

**建议B：实时监控 + 回退机制**
```python
def adaptive_generate_with_monitoring(
    model, tokenizer, passages,
    initial_ratio=0.3,
    fallback_ratio=0.7,
    attention_threshold=3.0
):
    # 同时维护两个KV cache
    cache_low = prepare_cache(ratio=initial_ratio)
    cache_high = prepare_cache(ratio=fallback_ratio)

    generated_tokens = []
    use_fallback = False

    for step in range(max_new_tokens):
        # 使用当前cache生成
        current_cache = cache_high if use_fallback else cache_low
        token, attention = generate_step(current_cache)

        # 计算attention差异（与high ratio对比）
        if not use_fallback:
            attn_low = attention
            _, attn_high = generate_step(cache_high, force_token=token)
            attn_l2 = compute_l2(attn_low, attn_high)

            # 如果差异过大，切换到高ratio
            if attn_l2 > attention_threshold:
                print(f"Step {step}: Attention L2={attn_l2:.2f}, switching to fallback")
                use_fallback = True
                # 从cache_high重新生成当前token
                token, _ = generate_step(cache_high)

        generated_tokens.append(token)
        if token == eos_token:
            break

    return generated_tokens
```

**收益**：
- 大部分情况下使用低ratio（Query部分）
- 检测到问题时立即切换到高ratio（Answer关键部分）
- 相比全程使用高ratio，仍能节省50-70%计算

**挑战**：
- 需要同时维护两个cache，内存开销增加
- 每步都要计算attention差异，有额外计算成本

### 2.1 改进Token Selection策略

**当前问题**：Selection算法可能只基于"重要性"单一维度，导致丢失"1216"。

**建议D：多目标Token Selection**

**当前策略（推测）**：
```python
# 可能的现有实现
def select_tokens_simple(embeddings, query_embedding, ratio=0.3):
    # 计算相似度
    similarities = cosine_similarity(embeddings, query_embedding)

    # 选择top-k
    k = int(len(embeddings) * ratio)
    top_indices = np.argsort(similarities)[-k:]

    return top_indices
```

**改进策略**：
```python
def select_tokens_multi_objective(
    embeddings,
    query_embedding,
    ratio=0.3,
    diversity_weight=0.3,
    coverage_weight=0.2
):
    """
    多目标选择：相似度 + 多样性 + 覆盖度
    """
    n_tokens = len(embeddings)
    k = int(n_tokens * ratio)

    # 1. 相似度得分（原有策略）
    similarity_scores = cosine_similarity(embeddings, query_embedding)

    # 2. 多样性得分（避免选择太相似的tokens）
    diversity_scores = compute_diversity(embeddings)
    # 使用MMR (Maximal Marginal Relevance)
    # 既要相似，又要彼此不同

    # 3. 覆盖度得分（确保答案的多方面都被覆盖）
    # 使用聚类识别不同的信息点
    clusters = kmeans(embeddings, n_clusters=5)
    coverage_scores = compute_cluster_coverage(clusters)

    # 综合得分
    final_scores = (
        similarity_scores +
        diversity_weight * diversity_scores +
        coverage_weight * coverage_scores
    )

    # 选择top-k
    selected_indices = np.argsort(final_scores)[-k:]

    return selected_indices


def compute_diversity(embeddings):
    """
    计算每个token的多样性贡献
    避免选择太多相似的tokens
    """
    n = len(embeddings)
    diversity_scores = np.zeros(n)

    for i in range(n):
        # 与其他tokens的平均距离
        distances = np.linalg.norm(embeddings - embeddings[i], axis=1)
        diversity_scores[i] = np.mean(distances)

    return diversity_scores


def compute_cluster_coverage(clusters):
    """
    确保每个cluster都有代表被选中
    避免只选择一个信息点
    """
    n_clusters = len(np.unique(clusters))
    coverage_scores = np.zeros(len(clusters))

    for cluster_id in range(n_clusters):
        # 该cluster的成员
        mask = (clusters == cluster_id)
        # 给该cluster的成员加分，确保被选中
        coverage_scores[mask] += 1.0 / np.sum(mask)

    return coverage_scores
```

**具体到当前case**：
- "1216"和"1220"可能属于不同的clusters（两个不同的事件）
- 多样性约束会确保两个cluster都有代表被选中
- 避免只选择"1220"相关的高频tokens

**实现建议**：
1. 先用简单聚类分析documents，识别"信息点"（如时间、地点、人物）
2. 确保每个信息点至少有代表性tokens被保留
3. 在保留预算内，优先选择与query最相关的

### 2.2 问题类型感知的自适应Ratio

**观察**：不同类型的问题对信息完整性要求不同。

**建议E：基于问题模式的Ratio调度**

```python
class AdaptiveRatioScheduler:
    def __init__(self):
        self.patterns = {
            'single_fact': {
                'regex': r'(What|Who|Where) is the .* of',
                'ratio': 0.3,
                'reason': '单一事实查询，信息集中'
            },
            'temporal_sequence': {
                'regex': r'When .* (first|second|again|multiple|both)',
                'ratio': 0.7,
                'reason': '时序问题，可能有多个时间点'
            },
            'enumeration': {
                'regex': r'(all|both|multiple|list) .* (were|was|did)',
                'ratio': 0.7,
                'reason': '枚举型问题，需要完整信息'
            },
            'comparison': {
                'regex': r'(compare|difference|similar|versus)',
                'ratio': 0.8,
                'reason': '对比问题，需要多方面信息'
            },
            'default': {
                'ratio': 0.5,
                'reason': '默认中等ratio'
            }
        }

    def select_ratio(self, question: str) -> tuple[float, str]:
        """
        根据问题模式选择合适的ratio

        Returns:
            (ratio, reason)
        """
        question_lower = question.lower()

        for pattern_name, config in self.patterns.items():
            if pattern_name == 'default':
                continue

            if re.search(config['regex'], question_lower):
                return config['ratio'], config['reason']

        return self.patterns['default']['ratio'], self.patterns['default']['reason']

# 但如果问题是 "When was Henry III first crowned?"
# 会被识别为temporal_sequence，ratio=0.7

print(f"Selected ratio: {ratio}")
print(f"Reason: {reason}")
```

### 2.3 层级式Recomputation

**问题**：当前是"全或无"的策略（要么保留token，要么丢弃）。

**建议F：渐进式Recomputation**

```python
class HierarchicalRecompute:
    def __init__(self, ratios=[0.3, 0.6, 1.0]):
        """
        三级缓存策略：
        - Level 1 (30%): 最重要的tokens，总是recompute
        - Level 2 (30%): 次重要的tokens，conditionally recompute
        - Level 3 (40%): 不重要的tokens，never recompute
        """
        self.ratios = ratios

    def select_hierarchical_tokens(self, embeddings, query_embedding):
        similarities = cosine_similarity(embeddings, query_embedding)
        n = len(embeddings)

        # Level 1: Top 30%
        k1 = int(n * 0.3)
        level1_indices = np.argsort(similarities)[-k1:]

        # Level 2: Next 30%
        k2 = int(n * 0.6)
        level2_indices = np.argsort(similarities)[-k2:-k1]

        # Level 3: Bottom 40%
        level3_indices = np.argsort(similarities)[:-k2]

        return {
            'always_recompute': level1_indices,
            'conditional_recompute': level2_indices,
            'never_recompute': level3_indices
        }

    def generate_with_hierarchical_cache(
        self,
        model,
        hierarchical_indices,
        dynamic_threshold=3.0
    ):
        """
        生成时动态决定是否使用Level 2
        """
        # 初始只使用Level 1
        current_indices = hierarchical_indices['always_recompute']
        cache = prepare_cache(current_indices)

        for step in range(max_new_tokens):
            token, attention = generate_step(cache)

            # 监控attention差异
            attn_l2 = monitor_attention_divergence(...)

            if attn_l2 > dynamic_threshold:
                # 动态扩展到Level 2
                print(f"Step {step}: Expanding to Level 2")
                current_indices = np.concatenate([
                    hierarchical_indices['always_recompute'],
                    hierarchical_indices['conditional_recompute']
                ])
                cache = prepare_cache(current_indices)
                # 重新生成当前token
                token, attention = generate_step(cache)

            ...
```

**收益**：
- 正常情况：只用30%，最快
- 检测到问题：扩展到60%，平衡
- 极端情况：可以进一步扩展到100%
- 动态适应不同难度的问题

### 3.1 学习最优Selection策略

**建议G：基于强化学习的Token Selection**

```python
class LearnedTokenSelector:
    """
    将token selection视为序列决策问题

    State: 当前已选tokens + query embedding + 剩余budget
    Action: 选择下一个token加入
    Reward: 最终答案质量（F1, ROUGE, etc.）
    """

    def __init__(self):
        self.policy_network = PolicyNetwork(
            input_dim=embedding_dim + context_dim,
            output_dim=1  # 选择概率
        )

    def select_tokens_rl(self, embeddings, query_embedding, budget):
        selected = []

        for step in range(budget):
            # State: 当前已选 + query + 剩余budget
            state = self.encode_state(selected, query_embedding, budget - step)

            # 候选：未选的tokens
            candidates = [i for i in range(len(embeddings)) if i not in selected]

            # Policy network预测每个候选的价值
            scores = self.policy_network(state, embeddings[candidates])

            # 选择最高分的
            best_idx = candidates[np.argmax(scores)]
            selected.append(best_idx)

        return selected

    def train(self, training_data):
        """
        训练数据：(question, documents, ground_truth_answer)

        训练过程：
        1. 用当前policy选择tokens
        2. 生成答案
        3. 计算reward（与ground truth对比）
        4. 更新policy（policy gradient）
        """
        for question, documents, gt_answer in training_data:
            # Rollout
            selected_tokens = self.select_tokens_rl(...)
            generated_answer = generate_with_selected_tokens(...)

            # Reward
            reward = compute_f1(generated_answer, gt_answer)

            # Update
            self.policy_network.update(reward)
```

**优势**：
- 直接优化最终答案质量，而不是中间指标（如相似度）
- 可以学习到复杂的模式（如"保留多样性"）
- 可以针对特定domain fine-tune

**挑战**：
- 需要大量标注数据
- 训练成本高
- 泛化性需要验证

### 3.2 答案完整性建模

**建议H：显式建模"信息点"覆盖**

**核心思想**：将答案建模为多个信息点的组合。

```python
class AnswerCompletenessModel:
    """
    学习识别答案的"信息点"
    确保每个信息点都被覆盖
    """

    def __init__(self):

        - InfoPoint1: {type: 'date', value: '1216', context: 'Gloucester'}

            info_points = [e for e in entities if e['type'] == 'DATE']
        elif question_type == 'location':
            info_points = [e for e in entities if e['type'] == 'LOCATION']
        ...

        return info_points

    def check_coverage(self, selected_tokens, info_points):
        """
        检查选中的tokens是否覆盖了所有信息点
        """
        covered_points = []

        for point in info_points:
            # 检查该信息点的相关tokens是否被选中
            point_token_indices = self.find_related_tokens(point, documents)

            if any(idx in selected_tokens for idx in point_token_indices):
                covered_points.append(point)

        coverage_ratio = len(covered_points) / max(len(info_points), 1)
        return coverage_ratio, covered_points

    def guided_token_selection(self, embeddings, query_embedding, info_points, budget):
        """
        基于信息点的guided selection
        """
        selected = []

        # 第一阶段：确保每个信息点至少有一个token
        for point in info_points:
            point_tokens = self.find_related_tokens(point, documents)
            # 选择该信息点的最佳代表token
            best_token = self.select_best_representative(point_tokens, query_embedding)
            selected.append(best_token)

        # 第二阶段：用剩余budget选择其他重要tokens
        remaining_budget = budget - len(selected)
        other_tokens = self.select_by_similarity(
            embeddings,
            query_embedding,
            k=remaining_budget,
            exclude=selected
        )

        selected.extend(other_tokens)
        return selected
```

### 3.3 Uncertainty-Aware Generation

**建议I：引入不确定性估计**

**问题**：Rate=0.3对"1220"有100%置信度，但实际上应该"不确定是否还有其他加冕"。

```python
class UncertaintyAwareGenerator:
    def __init__(self, model, ensemble_size=5):
        self.model = model
        self.ensemble_size = ensemble_size

    def generate_with_uncertainty(self, cache, max_tokens):
        """
        使用ensemble方法估计不确定性
        """
        # 生成多个候选（使用dropout或不同的selection）
        candidates = []

        for i in range(self.ensemble_size):
            # 每次使用略微不同的token selection
            perturbed_cache = self.perturb_cache(cache, perturbation=0.1)
            answer = generate(perturbed_cache, max_tokens)
            candidates.append(answer)

        # 分析一致性
        if len(set(candidates)) == 1:
            # 所有候选一致
            uncertainty = 'low'
            confidence = 1.0
        else:
            # 候选不一致
            uncertainty = 'high'
            # 计算答案多样性
            diversity = compute_answer_diversity(candidates)
            confidence = 1.0 - diversity

        # 返回最常见的答案 + 不确定性
        most_common = mode(candidates)

        return {
            'answer': most_common,
            'confidence': confidence,
            'uncertainty': uncertainty,
            'alternatives': list(set(candidates))
        }

```

## 五、评估指标

为了衡量改进效果，建议建立以下评估体系：

### 5.1 答案质量指标

```python
# 1. Completeness Score
def compute_completeness(generated, ground_truth):
    """
    答案完整性：生成的信息点 / 真实答案的信息点
    """
    gen_info_points = extract_information_points(generated)
    gt_info_points = extract_information_points(ground_truth)

    covered = len(gen_info_points & gt_info_points)
    total = len(gt_info_points)

    return covered / max(total, 1)

# 2. Precision/Recall/F1
def compute_f1(generated, ground_truth):
    gen_tokens = set(tokenize(generated))
    gt_tokens = set(tokenize(ground_truth))

    precision = len(gen_tokens & gt_tokens) / max(len(gen_tokens), 1)
    recall = len(gen_tokens & gt_tokens) / max(len(gt_tokens), 1)
    f1 = 2 * precision * recall / max(precision + recall, 1e-10)

    return precision, recall, f1
```

### 5.2 效率指标

```python
# 1. Speedup Ratio
speedup = time_baseline / time_optimized

# 2. Token Recompute Ratio
recompute_ratio = n_recomputed_tokens / n_total_tokens

# 3. Trade-off Efficiency
# 在保持答案质量的前提下，加速了多少
efficiency = f1_score / recompute_ratio
```

### 5.3 可靠性指标

```python

failure_rate = n_incomplete_answers / n_total_questions
```

## 六、总结

### 核心建议优先级

**立即实施（短期收益）**：
1. ✅ 双路径验证（建议A）- 最高ROI
2. ✅ 问题类型自适应（建议E）- 零额外成本
3. ✅ Logits预警（建议C）- 提供可观测性

**重点研发（中期）**：
4. ⭐ 多目标Token Selection（建议D）- 根本性改进
5. ⭐ 层级式Recomputation（建议F）- 灵活性提升

**探索方向（长期）**：
6. 🔬 答案完整性建模（建议H）- 质量保证
7. 🔬 学习最优Selection（建议G）- 自动优化

### 关键洞察

1. **不要盲目追求低ratio**：
   - 30%不是所有问题的最优选择
   - 应该基于问题特性动态调整

2. **验证比预防更实用**：
   - 很难保证selection总是完美
   - 更实际的是快速检测失败并fallback

3. **答案完整性 > 计算效率**：
   - 不完整的答案比慢答案更糟糕
   - 宁可多算10%，不要丢失关键信息

4. **可观测性很重要**：
   - 需要知道什么时候方法失败了
   - Attention L2、Logits差异等都是有用的信号
